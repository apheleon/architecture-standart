### <a name="_3bfxc9a45514"></a>**Функциональные требования**

|**№**|**Действующие лица или системы**|**Use Case**|**Описание**|**Комментарий**|
| :-: | :- | :- | :- |:- |
|UC1|Клиент|Запрос в кол-центр для получения информации|1. Звонок попадает в кол-центр где происходит балансировка вызова<br>2. Вызов может быть|Клиент попадает на IVR для распределения по очередям. Например: если вы клиент - нажмите 1
|UC2|Сотрудник кол-центра|Просмотр персональных ставок по депозитам, общие ставки|1. Сотрудник обращается через интерфейс CRM в прокси сервис<br>2. Получает список стакок по депозитам в реальном времени|CRM имеет доступ в прокси-сервис
|UC3|Сотрудник стороннего кол-центра|Обработка запроса от клиента банка|1. Сотрудник обращается к файлу насположенному на SFTP сервере<br>2. Получает список ставок по депозитам в реальном времени|Обработка обращения по согласованному сценарию с использованием файла с SFTP


### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**

|**№**|**Требование**|
| :-: | :- |
|R1|Актуальный файл на SFTP сервере должен быть готов в 99.9% обращений|
|R2|Прокси-сервис должен иметь горячий кэш ставок по депозитам 99.9% времени|
|P1|Время ответа прокси-сервиса ~300мс|
|P2|Время скачивания файла со ставками < 1сек. Файл следует шардировать, например по номеру хэшу от номера телефона|
|P3|АБС отвечает прокси-сервису за 100мс|
|+R1|Информация предоставляемая кол-центром банка и сторонней организацией одинакова|
|+R2|Микросервисная архикектура, Kubernetes|
|+S1|Стек реализации нового функционала неизменен|
